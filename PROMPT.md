## КОНТЕКСТ
Школьный исследовательский проект **«ЭкоСвет: как уменьшить расход электроэнергии в школе»**
(КГУ «Специализированная школа-лицей» управления образования Павлодарской области «Жас дарын»).

**Практическая ценность:** провести школьный энергоаудит освещения, найти источники нерационального потребления электроэнергии и разработать правила энергосбережения.

Исходные данные — 5 поэтажных планов эвакуации (JPG):
1. `floor1.jpg` — основное здание, 1 этаж (кабинеты, директор, приёмная, робототехника, информатика, медблок, столовая и пищеблок, санузлы, коридоры, холл, гардероб);
2. `floor2.jpg` — основное здание, 2 этаж (химия, биология, физика с лаборантскими, учительские, бухгалтерия, актовый зал, костюмерная, кабинеты, коридоры);
3. `astana127.jpg` — здание по ул. Астана, 127 (помещения с номерами и площадями в м² прямо на плане);
4. `gym1.jpg` — спортзал, 1 этаж (спортзал, раздевалка, душ, санузлы, электрощитовая, тепловой узел, кабинеты, снарядная);
5. `gym2.jpg` — спортзал, 2 этаж (4 кабинета, коридор, галерея).

## ЦЕЛЬ ПРИЛОЖЕНИЯ
Интерактивная «энергокарта» школы: на каждом плане отмечаются помещения и точки освещения (лампы). По ним считаются освещённость, потребление и стоимость электроэнергии. Формируются паспорта кабинетов и паспорт школы, SWOT-анализ, рекомендации и ИИ-анализ.

## ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 1. Роли и доступ
- **Администратор** — единственный, кто может редактировать: карты, помещения, лампы, тарифы, нормы, каталог ламп, SWOT, пользователей; отвечает на отзывы.
- **Пользователь (наблюдатель)** — свободная регистрация (логин + пароль), видит все данные только для чтения и может **оставлять отзывы** администрации об электроэнергии и экономии.
- Гость без входа видит только страницу входа/регистрации.
- Пароли — хэш PBKDF2-SHA256 с солью. Первый админ создаётся из `st.secrets` / переменных окружения (`ADMIN_USERNAME`, `ADMIN_PASSWORD`); если их нет — `admin / admin123` с предупреждением сменить пароль.
- Админ может повышать пользователя до админа и понижать обратно, сбрасывать пароли.

### 2. Интерактивные карты
- Выпадающий список: выбор каждого плана **отдельно**.
- На изображении поверх плана рисуются: контуры помещений (цвет = статус освещённости: 🟢 норма, 🟡 ниже нормы, 🔴 сильно ниже нормы, 🔵 пересвет/перерасход), точки ламп (жёлтые кружки с «ореолом», цвет по типу: LED / люминесцентная / накаливания / ДРЛ), подписи.
- **Инструмент «✏️ Карандаш» (только админ)** на базе `streamlit-image-coordinates`:
  - `💡 Поставить лампу` — клик по плану ставит лампу выбранного типа; помещение определяется автоматически по попаданию в контур;
  - `🧽 Ластик` — клик удаляет ближайшую лампу;
  - `▭ Разметить помещение` — два клика задают прямоугольник нового помещения / перерисовывают выбранное;
  - `🔎 Выбор` — клик выбирает помещение и показывает его мини-паспорт.
- Если компонент не установлен — запасной режим с ручным вводом координат X/Y.
- Админ может загрузить **новую карту** (PNG/JPG) и удалить карту.

### 2а. Окна и двери → естественное освещение
- Условные знаки плана: **окно** — участок стены без синего, светлый, с тонкими серыми параллельными линиями;
  **дверь** — белый разрыв между двумя синими блоками стены.
- Модуль `core/openings.py`: для каждой стороны контура помещения найти линию стены (максимум синего в полосе ±12 px),
  классифицировать столбики поперёк стены (стена / окно / разрыв), выделить окна (≥ 6 px) и двери (разрыв 5–40 px между стенами).
- Перевод px → м по площади помещения; площадь остекления = ширина × высота окна (настройка).
- Расчёт: световой коэффициент, **КЕО = T·Aок·θ° / (Aпов·(1 − R²))**, дневная освещённость, доля экономии от дневного света;
  сравнение КЕО с ориентиром по типу помещения.
- На карте окна — голубые линии, двери — коричневые; кнопка «🔍 Распознать окна и двери» (админ); ручная правка в паспорте.
- Для спортзала учитываются окна «второго света» с плана 2 этажа спортзала.

### 2б. Сохранение правок
- Правки карты (карандаш/ластик) копятся в черновике и записываются кнопкой «💾 Сохранить изменения» одной транзакцией;
  есть «↩️ Отменить» и предупреждение о несохранённых изменениях.
- Лампы, добавленные в паспорте, автоматически получают точку внутри контура помещения.
- После каждого сохранения снимок базы (JSON) пишется в GitHub (secrets: GITHUB_TOKEN, GITHUB_REPO, ветка ecosvet-data);
  при запуске с пустой базой — автоматическое восстановление; при сбое загрузки — запрет перезаписи.

### 3. Каталог ламп
Для каждой модели: название, технология (LED / люминесцентная / КЛЛ / накаливания / ДРЛ / галогенная), **мощность (Вт)**, **световой поток (лм)**, светоотдача (лм/Вт, считается), срок службы (ч), цена (₸). Каталог редактирует админ. Значения по умолчанию — типовые и помечены как ориентировочные.

### 4. Паспорт кабинета (помещения)
Поля: название, план, тип помещения (кабинет, лаборатория, компьютерный класс, спортзал, коридор, санузел и т. д.), **площадь (м²)**, высота потолка, естественное освещение (окна да/нет), **часы работы освещения в день**, дней в месяц, учебных месяцев в году, наличие датчиков движения, примечание.
Таблица ламп помещения: модель, **количество**, **мощность (Вт)**, **суммарно (Вт и кВт)**, **световой поток (лм)**.
Расчёты в паспорте:
- суммарная мощность, Вт и кВт; удельная мощность, Вт/м²;
- суммарный световой поток, лм;
- **средняя освещённость** методом коэффициента использования: `E = N·Φ·U·MF / S` (U = 0,5, MF = 0,8, настраиваются);
- норма освещённости для типа помещения и % выполнения нормы;
- нужное количество ламп до нормы: `N = ⌈E_норм·S / (Φ·U·MF)⌉`;
- потребление: кВт·ч в день / месяц / год = `P(кВт) × часы × дни × месяцы`;
- **стоимость**: ₸ в день / месяц / год по тарифу (₸/кВт·ч, настраивается);
- выбросы CO₂ (кг, коэффициент сети настраивается);
- класс энергоэффективности помещения (A–E по удельной мощности на 100 лк).
Экспорт паспорта в CSV/Excel.

### 5. Паспорт школы по электроэнергии
Итоги по каждому плану и по всей школе: число помещений, ламп, установленная мощность (кВт), кВт·ч и ₸ за день/месяц/год, CO₂, доля LED, число помещений ниже нормы, ТОП-10 потребителей, графики. Экспорт в Excel (несколько листов) и JSON-резервная копия всей базы.

### 6. Калькулятор экономии
Сценарии с расчётом кВт·ч, ₸ и CO₂ в год, инвестиций и срока окупаемости:
1. Замена всех не-LED ламп на LED с сохранением/доведением освещённости до нормы;
2. Датчики движения в коридорах, санузлах, складах (−30 % часов);
3. Использование дневного света в помещениях с окнами (−15 %);
4. Сокращение времени работы освещения на N часов (выключение на переменах/после уроков);
5. Комбинированный сценарий.
Параметры сценариев настраиваются ползунками.

### 7. SWOT-анализ для экономии
Автоматически генерируется из данных (доля LED, перерасход, недосвет, окна, датчики, тариф) + админ может добавлять собственные пункты в каждый квадрант. Отображение в виде 4 цветных квадрантов.

### 8. Рекомендации и правила энергосбережения
Автоматические рекомендации по каждому помещению и по школе с приоритетом (высокий / средний / низкий) и эффектом в ₸/год. Отдельный блок «Правила энергосбережения школы» (памятка для учеников и персонала).

### 9. ИИ-анализ
Три уровня: **по помещению**, **по каждому плану**, **по всей школе**.
- Встроенный экспертный движок (без интернета): правила + расчёты → структурированный отчёт в Markdown (состояние, проблемы, рекомендации, экономический эффект, приоритеты).
- Опционально внешняя LLM: если в `secrets` задан `ANTHROPIC_API_KEY` или `OPENAI_API_KEY`, на модель отправляется JSON-сводка, и она пишет развёрнутый отчёт. Если ключа нет или запрос не прошёл — используется встроенный движок.

### 10. Отзывы
Пользователи оставляют отзыв: тема (электроэнергия / экономия / предложение / проблема), привязка к плану/помещению (опционально), оценка 1–5, текст. Админ видит все отзывы, отвечает, меняет статус (новый / в работе / решено). Пользователь видит свои отзывы и ответы.

## ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
- Python 3.10+, Streamlit ≥ 1.36, pandas, Pillow, openpyxl, streamlit-image-coordinates, requests.
- Структура:
```
ecosvet/
├── app.py                  # точка входа, авторизация, навигация
├── core/
│   ├── openings.py         # распознавание окон и дверей
│   ├── db.py               # SQLite: схема, CRUD, резервная копия
│   ├── auth.py             # хэширование, вход, регистрация, роли
│   ├── calc.py             # освещённость, потребление, стоимость, экономия
│   ├── seed.py             # начальные данные: 5 карт, помещения, лампы, каталог, нормы
│   ├── mapdraw.py          # отрисовка карт (Pillow)
│   ├── swot.py             # SWOT и рекомендации
│   ├── ai.py               # ИИ-анализ: встроенный + LLM
│   └── export.py           # Excel/CSV/JSON
├── ui/                     # страницы интерфейса
├── assets/maps/*.jpg       # планы
├── assets/fonts/           # шрифт с кириллицей для подписей
├── tests/test_calc.py      # pytest
├── .streamlit/config.toml, secrets.toml.example
├── requirements.txt, README.md, LICENSE, .gitignore
```
- Начальные данные (seed) — все помещения с 5 планов с примерными контурами и площадями (для Астана 127 — площади с плана), лампы расставлены сеткой внутри контуров; помечено «данные ориентировочные — уточните при обходе».
- Все расчёты — чистые функции в `core/calc.py`, покрыты тестами.
- Кэширование изображений, `st.session_state` для режимов карандаша.
- README: описание проекта, скриншоты, установка, запуск, деплой на Streamlit Community Cloud, методика энергоаудита, формулы.

## МЕТОДИКА ЭНЕРГОАУДИТА (для README и раздела «О проекте»)
